## Glossary

- **Host** — the app shell (`bootstrap-admin` / `bootstrap-server`) that turns a
  plugin list into a running app. Owns no domain logic.
- **Plugin** — a unit of capability. Admin plugins contribute routes/slots;
  server plugins contribute a NestJS module + (optionally) schema & migrations.
- **`AdminPlugin` / `ServerPlugin`** — the plugin factory + contract for each
  runtime. See [`ARCHITECTURE.md`](ARCHITECTURE.md).
- **Slot** — a named UI extension point (e.g. `SIDEBAR_NAV_SLOT`) a plugin
  defines and others contribute into, with no direct coupling.
- **DI port** — the server-side extension idiom: a `Symbol` token + interface a
  foundational plugin declares and injects `@Optional()`, bound by an
  implementing plugin (e.g. `CONTENT_ENTRY_EXTENSION`, declared by content-server
  and bound by i18n-server). The inversion keeps the package graph acyclic.
  A token binds **once** — Nest has no multi-provider — so a seam that must take
  any number of contributions is a **registry** instead (content's
  `CONTENT_READ_SCOPE`, the copilot's tool registrar).
- **Localization / locale group** — an `i18n: true` content type stores one row
  per locale; sibling rows share a `locale_group_id`. Locale behavior lives in
  `@orthacms/i18n-server` (behind `CONTENT_ENTRY_EXTENSION`), not in content.
- **`@InjectDatabase()`** — DI token for the shared Drizzle connection from
  `@orthacms/database`.
- **Resolve-from-source** — workspace packages are consumed straight from
  `src/index.ts` with no build step (`@orthacms/source` TS condition).
- **RBAC** — role-based access control. One global role per user (`admin`,
  `contributor`, `viewer`) → permission keys (`resource:action`), enforced by
  `@RequirePermissions` + `PermissionsGuard` (server) and `useHasPermission`
  (admin).
- **Workspace** — a tenant/grouping. **Membership** — an M:N user↔workspace link.
- **API token / workspace bucket** — a long-lived bearer credential for the
  **public content API** (`/api/v1/...`), minted in the admin's API Tokens page.
  Its _bucket_ is the set of workspaces it may read (`api_token_workspaces`, one
  or more); a request picks one with `X-Workspace-Id`. Model + management API:
  `identity/server`; the read API and its guards: `content/server`
  (`public-api/`). The **same** token also authenticates the GraphQL protocol at
  `/api/v1/graphql` (`content/graphql`) — one credential, two protocols.
- **Webhook endpoint / delivery** — a URL this CMS POSTs to when content
  changes, and one event's journey to one endpoint. An endpoint carries three
  filters (workspaces × event kinds × content types) where an **empty set means
  "everything, including what does not exist yet"** — the opposite of an API
  token's bucket, because a filter is not a grant. Delivery is at-least-once and
  unordered; a receiver deduplicates on `X-Orthacms-Event-Id` and verifies the
  HMAC in `X-Orthacms-Signature`.
- **MCP** — the Model Context Protocol, how an AI agent discovers and calls what
  a system can do. Ortha CMS is an MCP **server** (`@orthacms/mcp-server`,
  [ADR-0006](docs/adr/0006-cms-as-an-mcp-server.md)); the copilot separately
  plans to be an MCP **client** of an operator's systems — opposite directions,
  different features.
- **Tool / tool registry** — a named, permission-gated capability an agent can
  invoke (`content_create`), and the transport-neutral catalogue holding them. A
  plugin contributes tools via the `TOOL_PROVIDER` port; `ToolRegistry.call` is
  the single place a tool call is authorized, the analogue of
  `@RequirePermissions` on a route.
- **Transfer** — one export or import. Its **document** is the format-neutral
  shape both ends agree on (`@orthacms/transfer-domain`); its **depth** is how
  far past the selected records it reaches — one hop, by decision
  ([ADR-0014](docs/adr/0014-transfer-as-a-separate-plugin.md)).
- **Natural key** — the field values that identify a record across
  installations (a `slug`, an `sku`, an `email`), as opposed to its row id,
  which means nothing outside the database it came from. What an import matches
  on to tell "update that record" from "add a new one".
- **Activity event** — an append-only audit row. It is **not** written in the
  mutation's transaction: the mutation commits a **domain event** to the outbox
  in that transaction, and `activity`'s subscriber turns the audited kinds into
  rows once the dispatcher delivers them. Delivery is at-least-once, so the
  insert is keyed on the event id `ON CONFLICT DO NOTHING`.
- **`workspace_content`** — an access-control mapping (workspace → code-defined
  content type), **not** a content-storage table: it is the workspace's declared
  content surface, and `ContentGrantGuard` refuses any content route naming a
  type the open workspace was never granted. Entries themselves live in the
  tables generated from the host's content types. Owned by `workspaces/server`.
- **Segment / audience** — a named set of reader tags, and the reader-facing
  half of access: an entry names the segments it admits and the segments it
  refuses, a deny wins, and an empty allow list means everyone. Separate from
  RBAC and `workspace_content`, which answer who may _touch_ content rather than
  who may _read_ it. Inert until an audience exists.
- **Alarm rule / finding** — a workspace-defined check over content and what it
  flagged. A rule stores the records-list **filter tree verbatim** and is
  evaluated through content's own `EntryMatchQuery`, so it can only ever mean
  what the list means. It never blocks a write
  ([ADR-0015](docs/adr/0015-alarms-are-non-blocking.md)).
- **Storage provider** — the `StorageProvider` port (`@orthacms/media-domain`)
  a deployment binds exactly **one** implementation of
  ([ADR-0012](docs/adr/0012-one-storage-provider-per-deployment.md)). Asset rows
  hold a `storage_key` + `storage_provider` pointer; the bytes never touch the
  database.
- **SSO provider** — the `SsoProvider` port (`@orthacms/identity-domain`) an
  adapter implements (`provider-oidc`, `-github`, `-saml`, `-fake`), so a
  protocol can be added without identity or the adapters depending on each other
  ([ADR-0013](docs/adr/0013-sso-provider-port.md)).
- **ADR** — Architecture Decision Record. See [`docs/adr/`](docs/adr/README.md).

## Skills (machine-readable context)

The repository ships these skills, canonically under `.agents/skills/` and
mirrored into `.claude/skills/` by symlink: `accessibility`, `admin-e2e`,
`admin-plugin`, `agent-browser`, `open-pr`, `server-e2e`, `server-plugin`,
`shadcn`, and `ticket`.

Most encode an authoring convention — prefer the skill over reverse-engineering
one from code. Two are procedures instead: `open-pr` writes a pull request body
from the diff, and `ticket` drives a ticket through the agent pipeline in
[`docs/agent-pipeline.md`](docs/agent-pipeline.md). The three role subagents that
pipeline delegates to live under `.claude/agents/`, because the subagent format
is Claude-specific where a skill is not.
